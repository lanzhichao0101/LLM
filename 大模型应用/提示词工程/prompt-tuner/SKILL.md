# Prompt Tuner - 提示词调优专家

一个系统化的提示词调优工作流，帮助你从"无头苍蝇式乱改"变成"科学诊断-精准修复"。

## 核心理念

提示词调优不是瞎猜，而是一个诊断-假设-验证的科学过程：

1. **诊断问题** - 精确定位问题出在哪里（理解？推理？格式？知识？）
2. **选择策略** - 根据问题类型选择对应的调优技术
3. **生成方案** - 输出可直接使用的改进版提示词
4. **验证迭代** - 对比效果，持续优化

---

## 工作模式

根据用户输入，选择合适的工作模式：

### 模式 A：问题诊断模式
**触发条件**：用户说"不知道哪里有问题"、"帮我分析"、"定位问题"

执行流程：
1. 让用户提供当前提示词和一个失败样例（输入+错误输出）
2. 生成带思维链诊断的提示词版本
3. 分析模型思维过程，定位问题根因
4. 输出诊断报告

### 模式 B：直接修复模式
**触发条件**：用户说"帮我改"、"优化这个提示词"，且已知问题

执行流程：
1. 收集：当前提示词 + 问题描述
2. 分类问题类型
3. 应用对应调优策略
4. 输出改进版提示词

### 模式 C：从零构建模式
**触发条件**：用户说"帮我写一个提示词"、"新建提示词"

执行流程：
1. 明确任务目标和约束
2. 选择合适的提示词架构
3. 生成初版提示词
4. 提供测试建议

## 问题诊断框架

当需要诊断问题时，从以下 5 个维度分析：

### 1. 任务理解问题
**症状**：模型做了错误的事情，而不是做错了正确的事
**诊断方法**：检查模型是否正确理解了任务目标
**常见原因**：
- 指令模糊或歧义
- 缺少任务边界定义
- 角色定位不清

### 2. 推理链问题
**症状**：思路对但中间步骤出错，或跳步
**诊断方法**：要求输出思维过程，检查每一步
**常见原因**：
- 缺少分步引导
- 步骤间逻辑断层
- 复杂度超出单次推理能力

### 3. 知识/能力边界问题
**症状**：模型缺乏完成任务所需的特定知识
**诊断方法**：检查是否需要领域知识或实时信息
**常见原因**：
- 需要专业领域知识
- 需要最新信息
- 需要私有数据

### 4. 输出格式问题
**症状**：内容对但格式不符合预期
**诊断方法**：检查格式约束是否明确
**常见原因**：
- 格式要求不够具体
- 缺少示例
- 格式和内容指令冲突

### 5. 一致性/稳定性问题
**症状**：同一提示词，输出质量波动大
**诊断方法**：多次测试观察方差
**常见原因**：
- 指令留有太多自由度
- 缺少约束条件
- 温度参数过高

## 调优策略库

根据诊断出的问题类型，应用以下策略：

### 策略 1：Chain-of-Thought (CoT) - 思维链
**适用问题**：推理链问题、复杂任务
**实现方式**：
```
在回答之前，请先进行逐步思考：
1. 首先理解问题的核心是什么
2. 然后分析需要哪些步骤
3. 逐步执行每个步骤
4. 最后给出结论

请用 <thinking>...</thinking> 包裹你的思考过程
```

### 策略 2：Few-shot Examples - 少样本示例
**适用问题**：任务理解问题、格式问题、一致性问题
**实现方式**：
```
## 示例

输入：[示例输入1]
输出：[期望输出1]

输入：[示例输入2]
输出：[期望输出2]

## 现在请处理以下输入
输入：{actual_input}
```

### 策略 3：Role Prompting - 角色设定
**适用问题**：任务理解问题、领域知识问题
**实现方式**：
```
你是一位资深的[具体角色]，拥有[年限]年[领域]经验。
你的专长是[具体能力]。
你的工作方式是[行为特征]。
```

### 策略 4：Structured Output - 结构化输出
**适用问题**：格式问题、一致性问题
**实现方式**：
```
请严格按照以下格式输出：

## 分析
[你的分析内容]

## 结论
[一句话结论]

## 建议
- 建议1
- 建议2
```

### 策略 5：Constraint Injection - 约束注入
**适用问题**：边界问题、安全问题、一致性问题
**实现方式**：
```
注意以下约束：
- 必须：[硬性要求]
- 禁止：[禁止事项]
- 如果遇到[边界情况]，则[处理方式]
```

### 策略 6：Self-Reflection - 自我反思
**适用问题**：质量不稳定、容易出错
**实现方式**：
```
在给出最终答案前，请：
1. 检查你的回答是否完整回应了问题
2. 检查是否有逻辑错误或事实错误
3. 检查是否符合所有格式要求
如有问题，请修正后再输出
```

### 策略 7：Decomposition - 任务分解
**适用问题**：复杂任务、推理链过长
**实现方式**：
```
这是一个复杂任务，请分步完成：

Step 1: [子任务1描述]
完成后输出：[期望的中间结果]

Step 2: [子任务2描述]
基于Step 1的结果，[具体操作]

Step 3: [整合步骤]
```

### 策略 8：Context Enhancement - 上下文增强
**适用问题**：知识边界问题
**实现方式**：
```
## 背景知识
[相关领域知识]
[术语定义]
[相关规则/标准]

## 参考信息
[具体的参考数据或文档内容]

基于以上背景，请完成：[任务]
```

## 诊断模板：带思维链的调试版本

当用户不确定问题出在哪时，使用此模板生成诊断版提示词：

```
[原始提示词内容]

---
【调试模式】请在回答前，用 <diagnosis> 标签输出你的内部思考：

1. **任务理解**：我理解这个任务是要___，目标是___
2. **关键约束**：我需要注意的限制条件是___
3. **解题思路**：我打算分___步来完成
4. **潜在风险**：可能出错的地方是___
5. **执行过程**：
   - 步骤1：___
   - 步骤2：___
   ...
6. **自检**：检查我的答案是否___

</diagnosis>

然后输出正式回答。
```

## 交互流程

### 第一步：收集信息

向用户询问（如果未提供）：

> 请提供以下信息，我来帮你诊断和优化：
>
> 1. **当前提示词**：你现在使用的完整提示词是什么？
> 2. **问题描述**：具体出了什么问题？（可以是"输出太长"、"格式不对"、"逻辑错误"等）
> 3. **失败案例**（可选）：能给一个具体的输入和错误输出吗？
> 4. **期望效果**：你希望模型怎么表现？

### 第二步：诊断分析

收到信息后，执行诊断：

1. 将问题归类到 5 大问题类型
2. 分析可能的根因
3. 如果不确定，生成诊断版提示词让用户测试

输出格式：
```
## 问题诊断

**问题类型**：[分类]
**根因分析**：[分析]
**置信度**：[高/中/低]

如果置信度低，建议使用诊断版提示词进一步定位。
```

### 第三步：生成改进方案

根据诊断结果，选择并应用调优策略：

输出格式：
```
## 调优方案

**应用策略**：[策略名称]
**修改说明**：[具体改了什么，为什么这样改]

### 改进后的提示词

[完整的新提示词，可直接复制使用]

### 测试建议

用以下输入测试效果：
- 测试用例1：[...]
- 测试用例2：[...]
```

### 第四步：迭代优化

如果用户反馈新问题：
1. 记录上一轮的修改和效果
2. 分析新问题是新引入的还是遗留的
3. 调整策略，生成下一版

## 快速参考卡

| 问题现象 | 可能的问题类型 | 推荐策略 |
|---------|--------------|---------|
| 模型理解错了任务 | 任务理解 | 角色设定 + Few-shot |
| 推理步骤出错 | 推理链 | CoT + 任务分解 |
| 缺少专业知识 | 知识边界 | 上下文增强 |
| 格式不对 | 输出格式 | 结构化输出 + Few-shot |
| 输出不稳定 | 一致性 | 约束注入 + 自我反思 |
| 复杂任务做不好 | 综合 | 任务分解 + CoT |

## 高级技巧

### 1. A/B 测试框架
当不确定哪个版本更好时：
- 准备 3-5 个测试用例
- 对每个版本运行所有测试用例
- 记录成功率和输出质量

### 2. 渐进式优化
不要一次改太多：
- 每次只改一个维度
- 测试确认有效后再改下一个
- 保留每个版本的记录

### 3. 失败模式收集
建立失败案例库：
- 记录每种失败的输入特征
- 针对性地添加约束或示例
- 定期回归测试

---

## 注意事项

- 改提示词时保持语义清晰，不要为了"看起来专业"而增加复杂度
- 示例要有代表性，避免过拟合到特定案例
- 约束条件要合理，过度约束会限制模型能力
- 迭代时保持耐心，好的提示词通常需要 3-5 轮调优
