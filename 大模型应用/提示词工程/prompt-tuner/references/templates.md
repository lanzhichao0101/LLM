# 提示词模板库

本文档包含各种场景下的提示词模板，可根据需要选用和组合。

---

## 1. 基础结构模板

### 1.1 标准任务模板

```
# 角色
你是[角色描述]。

# 任务
[任务描述]

# 输入
{input}

# 要求
- [要求1]
- [要求2]

# 输出格式
[格式说明]
```

### 1.2 带示例的任务模板

```
# 任务说明
[任务描述]

# 示例
## 示例 1
输入：[示例输入]
输出：[示例输出]

## 示例 2
输入：[示例输入]
输出：[示例输出]

# 当前任务
输入：{input}
输出：
```

## 2. 思维链模板

### 2.1 显式 CoT

```
请解决以下问题。在给出答案前，请先进行逐步分析：

问题：{question}

请按以下格式回答：

<思考过程>
1. 首先，我需要理解...
2. 然后，分析...
3. 接下来，计算/推理...
4. 最后，得出结论...
</思考过程>

<答案>
[最终答案]
</答案>
```

### 2.2 Zero-shot CoT

```
{question}

让我们一步一步地思考这个问题。
```

### 2.3 结构化推理模板

```
# 任务
{task_description}

# 输入
{input}

# 分析框架
请按以下步骤进行分析：

## Step 1: 问题拆解
- 这个问题的核心是什么？
- 需要解决哪些子问题？

## Step 2: 信息识别
- 输入中的关键信息是什么？
- 有哪些隐含条件？

## Step 3: 逻辑推理
- 根据已知信息，可以推导出什么？
- 每一步推理的依据是什么？

## Step 4: 结论生成
- 综合以上分析，结论是什么？
- 置信度如何？

# 输出
[最终答案]
```

## 3. 自我反思模板

### 3.1 输出前检查

```
{original_prompt}

在输出最终答案前，请进行自我检查：

<自检清单>
□ 是否完整回答了所有问题？
□ 逻辑是否自洽，有无矛盾？
□ 是否符合所有格式要求？
□ 是否有明显的事实错误？
□ 是否遗漏了重要信息？
</自检清单>

如果发现问题，请修正后再输出。
```

### 3.2 双重检验模板

```
{task_description}

请完成以下两个阶段：

## 阶段一：初步答案
[给出你的初步回答]

## 阶段二：批判性审视
作为一个批评者，审视上述答案：
- 有什么潜在的问题或错误？
- 有什么可以改进的地方？
- 是否有遗漏的角度？

## 最终答案
综合以上分析，给出你的最终答案：
```

## 5. 约束与边界模板

### 5.1 严格约束模板

```
# 任务
{task}

# 硬性约束（必须遵守）
- ✅ 必须：{must_do}
- ❌ 禁止：{must_not_do}
- ⚠️ 边界：{boundary_conditions}

# 软性偏好（尽量遵守）
- 优先：{preferences}
- 风格：{style_guide}

# 特殊情况处理
- 如果遇到{edge_case_1}，则{handling_1}
- 如果遇到{edge_case_2}，则{handling_2}
- 如果无法确定，则{fallback_action}
```

### 5.2 安全边界模板

```
{task}

## 安全指南
在完成任务时，请注意：

### 应该做的
- [正向行为1]
- [正向行为2]

### 不应该做的
- [负向行为1]
- [负向行为2]

### 不确定时
如果遇到无法判断的情况，请：
1. 明确说明不确定性
2. 提供多个可能的方案
3. 建议用户进一步确认
```

## 6. 格式控制模板

### 6.1 JSON 输出模板

```
{task}

请严格按照以下 JSON 格式输出，不要有任何其他内容：

```json
{
  "field_1": "说明",
  "field_2": ["item1", "item2"],
  "field_3": {
    "nested_field": "值"
  }
}
```

注意：
- 所有字符串使用双引号
- 不要添加注释
- 确保 JSON 格式有效
```

### 6.2 表格输出模板

```
{task}

请以 Markdown 表格格式输出结果：

| 列名1 | 列名2 | 列名3 |
|-------|-------|-------|
| 值1   | 值2   | 值3   |

要求：
- 至少包含 {min_rows} 行数据
- 按 {sort_column} 列排序
```

### 6.3 分段输出模板

```
{task}

请按以下结构组织你的回答：

## 摘要
[用1-2句话概括核心观点]

## 详细分析
[详细的分析内容]

## 关键要点
- 要点1
- 要点2
- 要点3

## 建议行动
1. [行动1]
2. [行动2]
```

## 7. 诊断调试模板

### 7.1 完整诊断版本

```
{original_prompt}

---
【诊断模式】为了帮助我理解你的推理过程，请输出以下诊断信息：

<diagnostic_trace>

## 1. 任务解读
- 我理解的任务目标是：___
- 关键要求是：___
- 潜在的歧义点：___

## 2. 输入分析
- 输入的关键信息：___
- 输入中缺失的信息：___
- 需要做的假设：___

## 3. 策略选择
- 我选择的解决策略：___
- 选择这个策略的原因：___
- 备选策略：___

## 4. 执行步骤
- Step 1: ___
  - 结果: ___
- Step 2: ___
  - 结果: ___
- ...

## 5. 风险评估
- 可能出错的地方：___
- 我的应对方式：___

## 6. 最终检查
- 输出是否符合格式要求：[是/否]
- 是否回答了所有问题：[是/否]
- 置信度评估：[高/中/低]

</diagnostic_trace>

---
【正式输出】

[在这里输出正式答案]
```

### 7.2 轻量诊断版本

```
{original_prompt}

请在回答前，用一段话简要说明你的思路：
"我的理解是...，我打算...，最终输出..."

然后给出正式回答。
```

## 9. 组合策略示例

### 9.1 复杂推理任务（CoT + 约束 + 自检）

```
# 角色
你是一位逻辑分析专家。

# 任务
{complex_reasoning_task}

# 约束
- 每一步推理必须有明确依据
- 如果信息不足，明确指出假设
- 最终答案必须有置信度说明

# 分析过程
请按以下结构进行分析：

## 信息梳理
[列出已知条件和需要求解的内容]

## 逐步推理
### Step 1
- 推理：___
- 依据：___

### Step 2
- 推理：___
- 依据：___

[继续...]

## 自检
- 逻辑链是否完整：___
- 有无跳跃或漏洞：___

## 最终结论
[答案]
置信度：[高/中/低]
原因：[为什么是这个置信度]
```

## 使用指南

1. **不要照搬模板** - 根据具体任务调整
2. **模板可以组合** - 例如 CoT + 自检 + 格式控制
3. **先测试再确定** - 用 2-3 个测试用例验证效果
4. **保持简洁** - 不需要的部分就删掉，模板是工具不是枷锁
